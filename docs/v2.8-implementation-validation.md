## 主要改动

1. `functions/_lib/reference-bindings.js`：统一素材 ID、稳定 `@图片N` token、prompt segments 和供应商 `[ImageN]` 映射。引用绑定保存在镜头中，不依赖显示名称或仅一段文本。
2. `functions/_lib/reference-preflight.js`：逐项验证工作区/素材权限、存在性、视频用途、PNG/JPG/WebP 类型、文件可读性、8MB 单图和 30MB 合计大小；读取实际图片字节。外部图片不再仅因有 HTTPS URL 就视为成功；限制私网字面地址与重定向目标。
3. `POST /api/v1/assets/reference-preflight`：返回 `items/errors`，包含素材 ID、可读状态、可显示名称及失败原因；失败返回 422，不发送缺图请求。
4. `POST /api/v1/drama-projects/:id/video-tasks`：支持 prompt、referencedAssetIds、referenceBindings、generationParams；每个镜头提交时再次校验图片，并把实际字节写入供应商 `metadata.content`。失败保留该镜头输入和原因；重试复用原失败 Work Record。
5. 镜头 PATCH 保存引用 ID、绑定和 prompt segments；项目 PATCH 保存生成参数及当前镜头。既有失效引用不妨碍保存其他项目输入；替换素材时仍检查权限。
6. `ShotReferences.jsx`：键入 @ 或点击按钮选择上传素材；按当前选择区间插入；显示缩略图、名称、编号、状态；支持预览、替换、移除和重新预检。素材选择器通过 portal 弹出，避免出现在页面底部。选择列表可分页加载。
7. `DramaVideoStage.jsx`：生成前预检未完成/失败时禁用；提交时显示 loading 并锁定会被服务端快照覆盖的编辑项；侧栏高度依据实际可用视口计算，设置滚动区和生成区分离。
8. `DramaProjectWorkbench.jsx`：提交前逐镜头预检并防重复点击；保存失败提供重试；返回项目列表前保存编辑；恢复保存的镜头与参数；视频归档失败刷新结果状态并允许重试。
9. 图片、视频归档显式记录 `pending/archived/archive_failed`；视频归档使用固定资产 ID，失败后保留播放地址并重试；生成结果记录实际使用的素材 ID。
10. 任务中心以较新的持久化状态为准，避免旧失败任务覆盖当前重试进度。圆环仍按单项真实进度显示，不求平均。
11. `server/railway.mjs` 增加可选 `SANHUA_BIND_HOST`，本地验证只监听 127.0.0.1；生产默认监听行为未改。
